# 📋 ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
## Программно-аппаратный комплекс «Сетка Чудиков» (Grid Creatures Engine)

---

### 1. ОБЩИЕ СВЕДЕНИЯ И НАЗНАЧЕНИЕ

**1.1. Наименование проекта:**  
Интерактивный симулятор биомеханики, эволюции и многопользовательская физическая 2D-песочница «Сетка Чудиков» (Grid Creatures).

**1.2. Назначение системы:**  
Программный комплекс предназначен для моделирования биомеханического движения сочлененных существ («чудиков») на основе законов классической ньютоновской механики, гидродинамики и теории графов; интерактивного проектирования организмов пользователями через визуальный конструктор; проведения многопользовательских симуляций в реальном времени с конкуренцией за ресурсы.

---

### 2. ЦЕЛИ И ЗАДАЧИ РАЗРАБОТКИ

- **Реалистичное моделирование биомеханики:** расчет поступательного и вращательного движения на основе распределения масс сегментов тела, работы мышечных приводов и моментов инерции (теорема Гюйгенса — Штейнера).
- **Высокая производительность:** обеспечение стабильной частоты физического тика 100 Гц (100 FPS) на серверной стороне с поддержкой сотен одновременных сущностей.
- **Интерактивность и удобство:** интуитивный визуальный векторный конструктор с мгновенной валидацией топологии тела (BFS), расчетом физических параметров и визуализацией векторов сил.
- **Сетевое взаимодействие:** синхронизация состояния мира между клиентами с минимальной задержкой через WebSocket с компенсацией сетевых лагов и интерполяцией.
- **Гибкость администрирования:** горячее переопределение физических констант мира без перезапуска сервера, детальное логгирование и управление аккаунтами.

---

### 3. ТРЕБОВАНИЯ К АРХИТЕКТУРЕ И ТЕХНОЛОГИЧЕСКОМУ СТЕКУ

#### 3.1. Архитектурная модель
Система построена по трехзвенной клиент-серверной архитектуре:
1. **Клиентская часть (Frontend SPA):** React 19 + TypeScript + Vite + Tailwind CSS + HTML5 Canvas.
2. **Шлюз / API сервер (Node.js Gateway):** Express + WebSocket Proxy + better-sqlite3 + JWT + bcryptjs (порт 3000).
3. **Физическое ядро (Backend Engine):** Высокопроизводительный сервер на языке Go (порт 8089).

#### 3.2. Стек технологий
| Компонент | Технологии | Назначение |
| :--- | :--- | :--- |
| **Фронтенд** | React 19, TypeScript, Tailwind CSS, Lucide React, HTML5 Canvas API | Отображение 60 FPS сцены, векторный конструктор SVG, панели управления |
| **Шлюз (Gateway)** | Node.js, Express, `ws`, `http-proxy-middleware` | Проксирование WebSocket, REST API, авторизация, отдача статики |
| **База данных** | SQLite (`better-sqlite3`), WAL-режим | Хранение профилей пользователей, хешей паролей и сохраненных чертежей чудиков |
| **Физический движок** | Go (Golang) 1.20+, Goroutines, Channels, `sync.RWMutex` | Цикл тика 100 FPS, Spatial Hashing, механика соударений, гидродинамика |

### 4. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

#### 4.1. Векторный Конструктор Чудиков
1. **Элементная база:**
   - **Голова (`head`)**: Задает направление движения «вперед» (0°, 90°, 180°, 270°), содержит челюсти для питания и сенсоры (глаза).
   - **Шарнир скелета (`joint`)**: Опорный узел вращения на пересечениях координатной сетки (вес = 0).
   - **Ребра жесткости (`edge-h`, `edge-v`, `edge-d1`, `edge-d2`)**: Горизонтальные, вертикальные и диагональные сегменты скелета (вес = 1).
   - **Мышцы (`muscle-left`, `muscle-right`)**: Мышечные волокна, создающие периодический крутящий момент относительно шарнира.
   - **Случайные мышцы (`muscle-random-left`, `muscle-random-right`)**: Мышцы с настраиваемой вероятностью срабатывания (5%–90%).
   - **Ластик (`eraser`)**: Удаление деталей.
2. **Правила крепления:** Мышцы крепятся строго к установленным шарнирам (`joint`).
3. **Валидация графа (BFS):**
   - Проверка связности всех элементов с головой.
   - Автоматическая подсветка изолированных («висящих») фрагментов предупреждающим контуром.
   - Блокировка сохранения и выпуска некорректных существ.
4. **Управление холстом конструктора:**
   - Изменение размера координатной сетки (от 5x5 до 15x15).
   - Панорамирование перетаскиванием мыши, масштабирование колесиком (30%–300%), центрирование и авто-вписывание чудика в экран.

#### 4.2. Физический движок и Биомеханика
1. **Теорема Гюйгенса — Штейнера:**
   - Расчет центра масс ($X_{CoM}, Y_{CoM}$) и тензора момента инерции $I_{zz} = \sum (I_{local,i} + m_i \cdot d_i^2)$.
2. **Модель мышц (Закон Гука с вязким демпфированием):**
   - Упруго-вязкая модель Кельвина — Фойгта: $F = -k(x - x_0) - c \cdot v_{rel}$.
   - Преобразование мышечных сокращений в крутящий момент $\tau = \vec{r} \times \vec{F}$ и угловое ускорение $\alpha = \tau / I_{zz}$.
3. **Гидродинамическое сопротивление (Drag):**
   - Экспоненциальное затухание скоростей: $v(t+\Delta t) = v(t) \cdot e^{-k_{lin} \Delta t}$, $\omega(t+\Delta t) = \omega(t) \cdot e^{-k_{ang} \Delta t}$.
4. **Непрерывное обнаружение столкновений (CCD):**
   - Расчет Time of Impact (ToI) для предотвращения туннелирования на высоких скоростях.
5. **Соударения и упругие импульсы:**
   - Массово-взвешенное разделение пересечений (Anti-Overlap).
   - Ньютоновский расчет контактных импульсов с учетом коэффициента упругости ($e$) и тангенциального трения с эффектом закручивания (Spin Effect).
6. **Оптимизация «Спящие острова» (Sleeping Islands):**
   - Автоматический перевод покоящихся существ в спящий режим для экономии процессорного времени.

#### 4.3. Игровые механики и Экосистема
1. **Тороидальный мир:** Непрерывное циклическое пространство с бесшовным переносом координат через границы.
2. **Еда и Метаболизм:**
   - Спавн питательных элементов (обычные, супер, золотые).
   - Поглощение еды при контакте с любым элементом тела или головой.
3. **Форсаж / Рывок (Dash Boost):**
   - Увеличение скорости в $1.6\times$ при зажатии клавиши «Пробел».
   - Расход ресурса: $2.0$ ед. еды в секунду. Блокировка при нулевом запасе еды.
4. **Каннибализм и Распад на компоненты:**
   - При укусе чужой головой элемент цели откусывается.
   - Тело жертвы пересчитывается: запускается поиск компонент связности. Меньшая оторванная часть погибает, большая сохраняет жизнеспособность.

#### 4.4. Сетевой протокол (WebSocket)
Синхронизация мира с частотой 100 Гц со структурой сообщений:
- `init`: инициализация сессии и привязка игрока.
- `state_sync`: дифференциальный снимок состояния (чудики, еда, силы, лидерборд).
- `input`: передача управляющих воздействий (угол курсора, флаг рывка `dash`).
- `spawn_creature`: отправка чертежа для создания нового существа в симуляции.
- `admin_control` / `set_rules`: удаленное управление сущностями и физическими параметрами.

#### 4.5. Пользовательский интерфейс и HUD
1. **Игровой холст (HTML5 Canvas):**
   - 60 FPS интерполяция движения между сетевыми тиками.
   - Свободная камера: центрирование, слежение за выбранным чудиком, зум.
   - 6 тем оформления: Тетрадь («notebook»), Чертеж («blueprint»), Темная («dark»), Бумага («paper»), Игра («game»), Светлая («game-light»).
2. **Динамический сглаженный HUD:**
   - Расчет габаритов тела (AABB) для исключения наложения текста на тело.
   - Экспоненциальное LERP-сглаживание по вертикали для устранения дрожания при взмахах крыльев и сгибах шарниров.
3. **Панели управления:**
   - Панель статистики и лидерборда (живые чудики на поле, сохраненные шаблоны).
   - Панель администратора с горячим редактированием физических констант `world_rules.json`.
   - Окно системных логов с фильтрацией по уровням (INFO, WARN, ERROR, FATAL).

#### 4.6. База данных и Безопасность
- Хранение аккаунтов в SQLite (`users`, `user_creatures`).
- Хеширование паролей через `bcrypt` (10 раундов соли).
- Аутентификация через JWT токены со сроком действия 7 дней.
- Предустановленный аккаунт администратора: `joni` / `PinokiO`.

### 5. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

1. **Производительность:** Серверный тик Go-ядра $\le 10$ мс (100 FPS), задержка рендеринга на клиенте $\le 16.6$ мс (60 FPS).
2. **Отказоустойчивость:** Автоматический перезапуск упавшего Go-процесса диспетчером Node.js в течение 1.5 секунд; сохранение работоспособности клиента в локальном офлайн-режиме при потере связи.
3. **Совместимость:** Корректное отображение в современных браузерах (Chrome, Firefox, Safari, Edge) с поддержкой Canvas и WebSocket.
4. **Контейнеризация и порты:** Работа всего веб-трафика и WebSocket-соединений через единый внешний порт `3000` (0.0.0.0).
